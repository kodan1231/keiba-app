# CSVインポート(テスト観点)

> `docs/TESTING.md` から機能単位で分割したテスト観点。関連仕様は `docs/design/csv-import.md`。
> 過去の日付単位の追記履歴は `archive/documents/pre-fix-v1.0/TESTING.md`。

## 1. CSVインポート

- 購入履歴 → CSVインポート
- 同じCSVを2回実行する
  - 1回目: レスポンスの `imported > 0`
  - 2回目: レスポンスの `skipped > 0`(重複を検知して取り込まない)
- 購入履歴に取込結果が表示されること
- 的中していない買い目も「未確定」ではなく「確定(払戻¥0)」表示になること
- 「的中／返還」列が完全に空(無記入)の行(=不的中)も、取込後に「未確定」ではなく
  「確定(払戻¥0)」表示になること(`docs/design/csv-import.md`「CSV取込の仕様」参照)
- 上記のCSVを取り込んだ後、レース管理画面・購入履歴画面等で該当グループの状態が
  「未確定」ではなく確定済みとして扱われていること(`imported_ticket_groups.status`が
  `'settled'`になったことの間接確認)
- v10より前の旧形式データ(`imported_tickets`のみに残っている、正規化前のレガシー行)が
  ある場合、そのレガシー行も「的中／返還」相当の情報が空(返還額0)であれば「未確定」
  ではなく「確定(払戻¥0)」表示になること
- CSV取込した購入履歴を削除できること(削除に失敗しないこと)
- 購入履歴に紐づくレースを削除すると、購入履歴側からもきちんと消えること
  (削除後、同じCSVを再取込した際に正しく取り込まれる=重複スキップにならないこと)
- 出走取消等による「返還」行を含むCSVがあれば、該当買い目の`payout`が0円(全損)ではなく、
  返還額(通常は購入額と同額=収支±0)相当になることを確認する(未検証の要確認事項。
  **これは「的中／返還」列に何らかの文字列(「的中」を含まない)が入っている行のケースで、
  列が完全に空の行(上記項目)とは別の未解決問題。`docs/BACKLOG.md`「調査中の不具合」参照**)

API確認:

```text
GET /api/ticket-imports
```

レスポンスが `{ ok: true, items: [...] }` の形式であること。

```text
POST /api/ticket-imports
```

`multipart/form-data` の `file` フィールドにCSVファイルを指定して取込めること。

- `sample/20260719_tohyo.csv`をインポートし、以下を確認する
  - 福島4Rのワイド(BOX・ながし)で、1行に複数の的中組み合わせがある場合に、
    組み合わせごとに正しい払戻金額が計上されること(合計が払戻金額列と一致すること)
  - 同じ受付番号・通番が別日に存在しても、日付が異なれば重複スキップされず正しく取り込まれること
  - インポート後、レース管理画面で福島4Rを開くと、1〜3着セレクトに着順(三連単の的中組み合わせ)が
    自動入力されていること
  - 同じくレース管理画面の払戻入力欄に、単勝・馬連・ワイド・三連複・三連単など
    複数式別の払戻レートが自動入力されていること
  - 単勝のみ的中しているレース(例: 函館6R)では、1着セレクトだけに馬番が自動入力され、
    2・3着は空のままであること

## 1.6 CSV取込データへの馬名・騎手の反映(バックフィル)

- 馬名・騎手が未登録のレースのCSVを取り込む(取込直後は`imported_ticket_items`の
  `selections`が馬番のみになっていることを想定)
- レース管理画面でそのレースの出走馬表(馬名・騎手)を登録して保存する
- 保存後、馬券履歴・集計(騎手別収支)画面で、そのCSV取込分の購入履歴にも
  馬名・騎手が反映されていること(空欄のままにならないこと)
- 既に馬名・騎手が入っている項目は、保存し直しても値が変わらない(上書きされない)こと
