# 払戻確定時のticket反映・結果確定後の購入表示(テスト観点)

> `docs/TESTING.md` から機能単位で分割したテスト観点。関連仕様は `docs/design/payout-refund.md`。
> 過去の日付単位の追記履歴は `archive/documents/pre-fix-v1.0/TESTING.md`。

## 1.7 払戻確定時のticket反映(全ユーザー対応)

- 一般ユーザーA(管理者ではないアカウント)で、あるレースの馬券を複数式別・複数点購入する
- 別の一般ユーザーB(管理者ではないアカウント)でも、同じレースの馬券を購入する
- 管理者アカウントでログインし、そのレースの着順・払戻レートを入力して保存する
  (**管理者自身はこのレースの馬券を1枚も購入していない状態**で確認するのが望ましい)
- ユーザーAでログインし直し、購入履歴画面・集計画面(レース別・競馬場別・騎手別)で
  該当馬券の払戻・的中/不的中が正しく反映されていること(「未確定」のままではないこと)
- ユーザーBでログインし直し、同様に払戻が正しく反映されていること
- 予想登録画面(`prediction.html`)の「このレースの購入馬券」欄でも、ユーザーA・Bそれぞれの
  払戻が正しく表示されること
- 管理者が後日、同じレースの払戻レートを修正(上書き)して保存した場合、ユーザーA・Bの
  購入履歴にも修正後の値が再反映されること
- 的中している買い目は正しい払戻額、的中していない買い目は¥0(確定)として反映されること
  (未確定=`null`のままにならないこと)
- 管理者自身が購入していないレースでも、払戻確定操作自体がエラーなく完了すること

### 1.7.1 JRAレース結果PDF一括登録での反映

上記1.7と同じ「全ユーザーへの反映」が、「JRAレース結果PDFをインポート」(一括登録)
経由で着順・払戻を確定させた場合にも正しく行われることを確認する。

- 一般ユーザーA・Bで、まだ結果未確定のレースの馬券を複数式別・複数点購入する
  (管理者アカウントはこのレースの馬券を購入していない状態が望ましい)
- 管理者が「JRAレース結果PDFをインポート」から、そのレースを含むPDFを解析・一括登録する
- 登録後、ユーザーA・Bの購入履歴画面・集計画面で、該当馬券の払戻・的中/不的中が
  正しく反映されていること(手動で払戻編集モーダルを開き直して再保存しなくても
  反映されていること)
- 同じPDFを再インポートして着順・払戻レートを更新した場合も、再反映されること
- 「戸崎」など、人名で異体字が使われる可能性のある騎手名を含むPDFをインポートし、
  購入履歴・予想登録・レース管理・集計画面のいずれでも、取り込まれた騎手名の字体が
  PDF上の表記と一致すること(詳細は「1.8 出走馬一覧PDFインポート」の「人名の異体字保持」
  参照)
- **2026-08-30追加**: 12レース分など、レース数の多いPDFを一括登録しても、途中で
  「一括登録に失敗しました」というエラーにならず、最後まで成功すること
  (`entries-import.js`/`results-import.js`のサブリクエスト数対策の確認。
  `docs/design/import-flow.md`「実装上の注意(サブリクエスト数対策)」参照)。ブラウザの開発者ツールの
  Networkタブで、`POST /api/races/results-import`が500エラーにならないことを確認する

### 1.7.2 枠番の自動計算・枠連の判定

**2026-08-30〜の仕様**: 馬番が確定していれば、出走頭数から枠番が自動計算されて
確定値としてDBに保存される(`docs/design/data-model.md`「枠番は馬番から自動計算して保存する」
参照)。以下を確認する。

- 出走馬一覧PDFインポート、またはJRAレース結果PDFインポートで馬番を確定させる
- 対象レースの出走馬表を確認し、全馬に枠番(1〜8)が自動的に入っていること
  (手動で確定済みの枠番がある場合は上書きされていないこと)
- 予想登録画面・購入画面で、各馬の枠番バッジ(色付き丸)が「−」ではなく実際の
  枠番で表示されること
- 上記のレースで枠連(wakuren)馬券を購入し、管理者が着順・払戻レート(枠連を含む)を
  確定させると、購入した枠連馬券の的中/不的中が正しく判定され、`payout`が
  「未確定」のまま残らないこと
- **既存レース(2026-08-30より前にインポート済みで、枠番がnullのまま残っている
  レース)**について、同じPDFを再度インポートし直すと、既存の`entries`に枠番が
  自動的に埋まること(マージ処理内で計算されるため、専用の一括補正操作は不要)
- 手動で枠番を確定済みの馬(出走馬表編集画面から入力したもの)がある場合、PDFの
  再インポートでその値が上書きされないこと(枠番が`null`の馬にのみ自動計算が
  適用されることの確認)
- 馬番自体が未確定(木曜等)のレースでは、従来通り枠番も`null`のまま(自動計算
  されない)であること(馬番が確定して初めて枠番も計算されることの確認)


## 4.5 レース確定後の購入表示(結果確定済ラベル)

- 着順(1〜3着)または払戻レートを登録済みのレースについて、
  予想画面の「このレースの馬券を購入」ボタンが「結果確定済(購入する)」という表示に変わり、
  見た目も変化すること(ただしクリックはでき、購入ページへ遷移できること)
- 確定済みレースのURL(`index.html?race=...`)に直接アクセスした場合、
  レース名見出しの横に緑色の「確定済」バッジが表示されること。購入UI自体は表示され、
  通常通り購入できること
- `POST /api/tickets/bulk`を確定済みレースのrace_idで直接叩いても、
  拒否されず購入が成功すること
- 着順・払戻が確定済みのレースに紐づく購入履歴でも、購入履歴画面から購入額・払戻・メモの
  編集、および削除ができること。`PUT /api/tickets/:id`・`DELETE /api/tickets/:id`を
  確定済みのチケットIDに対して直接叩いても、拒否されず成功すること
- 枠番・馬番が未確定のレースは、着順・払戻の確定有無にかかわらず「枠番・馬番未確定
  (購入不可)」表示になり、購入ページを開いても購入UIがブロックされること(詳細は1.8参照)

### 4.5.0 返還情報のみのレースで「確定済」バッジが誤表示されないこと

`docs/design/payout-refund.md`「払戻確定バッジ・的中率集計の判定」参照。JRAレース結果PDFインポートで
取消・除外・中止馬がいるレース(=`races.payouts.refunds`に情報が入るレース)を使って確認する。

- 出走馬に取消・除外・中止馬を含むJRAレース結果PDFを、**着順・払戻レートは未入力の状態**
  (または着順のみ確定し払戻レートは未入力の状態)でインポートする(あるいは、既存の
  該当レースが`races.payouts`に`refunds`キーのみを持つ状態になっていることをAPI
  レスポンス等で確認する)
- 実際の払戻レート(単勝・複勝等の式別データ)が1件も登録されていない場合、購入画面
  (`index.html`)でそのレースを開いても、レース名見出しの横に「確定済」バッジが
  **表示されない**こと
- 同じ条件で、予想登録画面(`prediction.html`)の「このレースの馬券を購入」ボタンが
  「このレースの馬券を購入」のまま(「結果確定済(購入する)」に変わらない)こと
- 集計画面(`stats.html`)の的中率集計で、このレースが判定対象(分母)に含まれない
  こと(着順・払戻レートのいずれも未確定であるため)
- その後、管理者が該当レースの払戻レート(実際の式別データ)を1件以上入力・保存すると、
  上記いずれの画面でも正しく「確定済」/「結果確定済」/的中率の判定対象に切り替わる
  こと(修正が過剰判定側に倒れていないことの確認)
- 取消・除外・中止馬がいない通常のレース(`payouts`に`refunds`キーが無いレース)では、
  従来通り着順または払戻レートの確定有無で正しく「確定済」表示が切り替わること
  (回帰確認)

### 4.5.1 結果確定済みレースへの購入時の払戻即時反映

過去に購入した馬券の履歴を残す目的で、既に着順・払戻が確定しているレースへ後から
購入した場合でも、購入と同時に払戻が計算・反映されることを確認する。

- 管理者が、あるレースの着順・払戻レート(複数式別)を確定させる
  (レース管理画面の払戻編集モーダル、またはJRAレース結果PDFインポートのいずれでもよい)
- 一般ユーザーが、確定済みのそのレースを`index.html`から新規購入する(的中する買い目・
  的中しない買い目の両方を含めて複数式別購入するとより確実に確認できる)
- 購入直後、`POST /api/tickets/bulk`のレスポンスが成功(`ok: true`)を返すこと
  (払戻の即時反映処理に失敗しても、購入自体は失敗しないこと)
- 購入後、ページ遷移・再読込をせずに購入履歴画面(`history.html`)・予想登録画面
  (`prediction.html`「このレースの購入馬券」欄)・集計画面のいずれかを開くと、
  該当馬券の払戻・的中/不的中が「未確定」ではなく、購入した時点で既に正しく
  反映されていること(レース管理画面で払戻を再保存し直す必要がないこと)
- 的中している買い目は正しい払戻額、的中していない買い目は¥0(確定)として即座に
  反映されていること
- 別のユーザーが同じレースを既に購入済みだった場合、そのユーザーの購入履歴
  (`tickets.payout`)が意図せず変わってしまわないこと(既に正しい値であれば、
  再計算しても同じ値のまま変化しないことを確認する)
- 未確定(着順・払戻とも未入力)のレースへ通常通り購入した場合は、従来通り
  `payout: null`(未確定)のまま保存されること(確定済みレースの場合とは異なり、
  即時反映処理自体は実行されるが計算結果に反映すべき情報がないため、`payout`は
  変化しないことを確認する)
- 枠番未確定の枠連馬券が絡む確定済みレースに購入した場合、`payout`が「¥0(不的中)」に
  誤って断定されず「未確定」のまま反映されること(1.7.2と同様の判定ロジックが
  このケースでも機能していることの確認)
