## 12. 騎手名エイリアス管理

**前提**: `migration.sql`の`-- @STEP: jockey_aliases`ブロックを事前に適用しておくこと
(`jockey_aliases`テーブルが存在しない状態だと、以下のAPI呼び出しが失敗する)。

### 12.0 セットアップ

```bash
npx wrangler d1 execute keiba-yosou-db --local --file=migration.sql
```

### 12.1 管理画面でのエイリアス登録・削除

- 管理画面(`admin.html`)に「騎手名エイリアス管理」セクションが表示されること
  (管理者のみ表示されることは既存の管理画面全体の権限制御に準ずる)
- 「表記ゆれ側」に「戸崎圭」、「正しい表記」に「戸崎圭太」を入力して追加すると、
  一覧に反映されること
- 同じ表記ゆれ(空白の有無違いを含む)を再度登録しようとするとエラーになること
  (例: 既に「戸崎圭太」を登録済みの状態で「戸崎 圭太」を登録しようとした場合、
  スペースの有無にかかわらず同一の`alias_key`になるため重複エラーになることを確認する)
- 一覧の削除ボタンでエイリアスを削除できること。削除後、一覧から即座に消えること
- 管理者以外のユーザーで`GET/POST /api/admin/jockey-aliases`・
  `DELETE /api/admin/jockey-aliases/:id`・`POST /api/admin/jockey-aliases/normalize-existing`
  を直接叩いても403エラーになること

### 12.2 今後登録されるデータの自動正規化

以下いずれの経路でも、`jockey_aliases`に登録済みの表記ゆれが自動的に「正しい表記」へ
統一されることを確認する。事前に「戸崎圭 → 戸崎圭太」をエイリアス登録した状態で行う。

- **手動入力(netkeibaテキスト貼り付けを含む)**: レース管理画面の出走馬表フォームで、
  騎手名欄に「戸崎圭」と入力(またはnetkeibaテキスト貼り付けで「戸崎圭」が読み取られた
  状態のまま)保存すると、保存後は「戸崎圭太」として表示・保存されること
- **出走馬一覧PDFインポート**: 解析結果の騎手名が「戸崎圭」だった場合(実PDFでの再現が
  難しければ、テスト用に解析結果を加工するか、単体テストで`entries-import.js`の
  マージ前正規化ロジックを確認する)、登録後は「戸崎圭太」として保存されること
- **JRAレース結果PDFインポート**: 同様に、`races.entries`・`race_results.jockey`の
  両方が正規化されて保存されること
- エイリアスに登録されていない表記(例: 未登録の別の騎手の空白揺れ)は変更されずに
  そのまま保存されること(誤爆しないことの確認)

### 12.3 既存データの一括補正

- 「戸崎 圭太」表記が既に保存されている状態(`races.entries`・`tickets.selections`等)を
  用意し、`jockey_aliases`に「戸崎圭 → 戸崎圭太」のみを登録した状態で「既存データの
  騎手名を一括補正する」ボタンを押す
- 実行確認ダイアログが表示され、OKすると一括補正が実行されること
- 完了後、更新件数(レース/レース結果/購入履歴/CSV取込)がメッセージとして表示されること
- `races.entries`・`race_results.jockey`・`tickets.selections`・
  `imported_ticket_items.selections`のうち、**エイリアスと一致した表記のみ**が
  書き換わり、一致しなかった表記(未登録の騎手名等)は変化しないこと
- 同じボタンをもう一度押しても、2回目は更新件数が0件になること(冪等性の確認。
  1回目で既に正しい表記へ揃っているため)
- 一括補正後、集計画面(`stats.html`)の騎手別収支で、同一騎手の収支が1行に統合されて
  表示されること(補正前は「戶崎 圭太」「戸崎圭」「戸崎 圭太」等が別行に分かれていた
  ものが統合されることを確認する)

### 12.4 見習い減量記号(☆▲△★◇)を含む場合

- 見習い記号付きの騎手名(例: 「☆戸崎圭」)を含むデータに対し、「戸崎圭 → 戸崎圭太」
  (記号なし)のエイリアスを登録した状態で正規化が行われると、記号を保持したまま
