# データ検索「騎手検索」タブ(テスト観点)

> `docs/TESTING.md` から機能単位で分割したテスト観点。関連仕様は `docs/design/data-search.md`「騎手検索タブ」。

## 14. 騎手検索タブ(2026-10-03追加)

### 14.0 前提

- DBの変更(マイグレーション)は不要。`races_cache`・`race_stats_cache`(既存の事前計算キャッシュ)から集計する

### 14.1 候補の絞り込み

- タブを開くと騎手一覧を1回だけ取得し、「騎手名の一部を入力してください(N人)」と出ること
- 1文字(例:「武」)から候補が出ること。候補は騎乗数の多い順で、各候補に「N騎乗」が出ること
- 空白の有無(「戸崎 圭」「戸崎圭」)、全角/半角、見習い減量記号(▲等)の有無に関係なく候補に出ること
- 該当なしの場合は「該当する騎手がいません」と出ること。51件以上該当する場合は上位50件と絞り込みの案内が出ること
- 入力を変えると、表示中の成績表が閉じること
- 入力をしている間、`/api/data-search/jockeys` 等へのリクエストが発生しないこと(開発者ツールのネットワークで確認)

### 14.2 成績表

- 候補を選ぶと、騎手名・対象期間(最初と最後の騎乗日)・通算/年度別/コース別の3つの表が出ること
- 各表の列が「騎乗数・1着・2着・3着・着外・単勝率・連対率・複勝率」であること(年度別・コース別は先頭に年度/コース)
- 通算の騎乗数 = 年度別の騎乗数の合計 = コース別の騎乗数の合計 であること
- 着外 = 騎乗数 − (1着+2着+3着)、単勝率 = 1着/騎乗数、連対率 = (1着+2着)/騎乗数、複勝率 = (1〜3着)/騎乗数 であること
- 年度別は新しい年が上、コース別は騎乗数の多い順であること
- コース別が「東京 芝1600m」のように競馬場×芝/ダート/障害×距離ごとに分かれていること。障害レースは「障」の行になること
- 取消・除外になった騎乗は騎乗数に入らないこと(結果の全頭データがあるレース)
- 結果の全頭データが無いレース(手入力・CSVのみ等)も、出走表+上位3着から集計に含まれること
- エイリアス登録済みの表記ゆれ(管理画面「騎手名エイリアス管理」)が同じ騎手にまとまること
- 別の候補をすばやく続けて押した場合、最後に押した騎手の成績が表示されること

### 14.3 レース成績タブへの影響(共通処理の切り出し)

- レース成績タブの「高勝率騎手/高複勝率騎手トップ5」「馬番別成績」が、変更前と同じ値で表示されること
  (`buildRaceLineup()` を `_lib/race-lineup.js` へ移しただけで、ロジックは変えていない)
