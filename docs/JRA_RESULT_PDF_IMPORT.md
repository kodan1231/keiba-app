# JRAレース結果PDFインポート — 統合ドキュメント

このドキュメントは docs/ 配下のJRAレース結果PDFインポート関連ドキュメントを整理・統合したサマリです。詳細ログは元ドキュメント（末尾）を参照してください。まず結論と現状サマリを示します。

## 結論（要点サマリ）
- 主要な「0件（解析がレースを検出できない）」不具合は、PDF.js抽出テキストの行内結合ロジック修正により解消済み（実機で12レース取得を確認、パーサーバージョン `8.0.0-gapjoin`）。
- **2026-08-09時点、パーサーは `8.1.0-jockey-order-waku` まで進んでいる（`public/jra-result-pdf.js`実装で確認済み）。** 旧調査記録で「実機再検証待ち」としていた①騎手抽出・②出走馬の並び順・③枠番算出のロジックはこのバージョンで実装済み。ファイル名が示す通り、騎手名の見習い印除去(`jraResultCleanJockeyName`)、entriesの馬番昇順ソート、枠番未取得時の`defaultWakuNumber()`によるフォールバック計算が含まれる。**ただし、この更新はコード上の実装確認によるものであり、実機(実ブラウザ)での③④の再検証記録はまだ見当たらない。次回セッションでは実機再検証の結果自体を確認・追記すること。**
- 払戻（金額/式別）の一部欠落は、`jraResultParsePayoutLine`が「組み合わせの頭数(1頭/2頭/3頭)ごとに直前式別を保持する」`carryState`方式に改善されており(2026-08-09付近の実装コメントで確認)、複数列にまたがる複勝・ワイド等の継続行の取りこぼしに対応した形跡がある。矢印区切り(→)への対応状況は未確認のまま。
- 次のアクション：実機（ブラウザ）での再インポートを行い、診断パネルの抽出全文を確認して①〜④すべての最終検証を完了すること。特に上記の通り、コード実装は先行しているがドキュメント側に実機検証結果の記録が追いついていない状態。

## 1. 影響と対象機能
- 対象：`races.html` の「JRAレース結果PDFをインポート」機能（ブラウザ側で PDF.js によるテキスト抽出 → パーサーで解析 → /api/races/results-import に POST）  
- 影響範囲：レース開始検出、開催情報（日付・競馬場・開催回）、着順（1〜3着）、出走馬データ、払戻（複数式別）などレース結果の自動取り込み全体。

---

## 2. 事象（症状）
- 実機でPDFファイルをインポートすると解析結果が「0レース」になるケースが発生（主報告日: 2026-08-05）。
- 診断から、PDF.js の抽出自体は行数等正常だが「発走時刻」「日付」「開催情報」などの文字列が正規表現で検出できないことを確認。

---

## 3. 原因分析（要点）
- PDF.js が返す行内のテキスト断片を単純にタブで結合していたため、文字列の内部（単語内）にもタブが入り込むケースがあった。これにより "発走時刻" 等の単語が分断され、既存の正規表現が不一致になる。
- また、PDF抽出により互換文字（例: U+Fxxxの互換漢字）や全角/半角コロンの差なども検出に影響していた。

重要な観察値（診断）
- 抽出行数は多数あるが「発走時刻」候補が0件、日付候補0件など。  
- 結合ロジックが間違った区切りを入れていることが最大要因。

---

## 4. 実施した修正（時系列）
以下は主要な修正とその目的。

### v3（正規化導入）
- 実施内容: `jraResultNormalizeText()` で `String.prototype.normalize("NFKC")` を適用。互換文字を標準形へ変換して正規表現のマッチ性を改善。
- 対処: 互換漢字や互換コロン等の差異を是正。

### v4（コロン等の許容）
- 実施内容: 正規表現の微修正（`発走時刻\s*[:：]` 等）や、日付/競馬場が別行になるケースの保持。キャッシュバスター更新。
- 対処: NFKC正規化による全角→半角変換後の不一致対策。

### v5（構造的改善）
- 実施内容: ページ跨ぎの解析状態維持、時刻/開催情報を基準にレース境界検出、払戻表解析の強化（横3列レイアウト対応）、entriesの取得拡張（1〜18着を entries として取得）、診断情報の画面表示など。
- 対処: PDF.js抽出のばらつきに強い構造化解析の拡張。

### gapjoin（v8.0.0-gapjoin）
- 実施内容（核心改修）: 行結合時に単純タブ連結を止め、テキスト断片間の実測ギャップを基に「連結 / 半角スペース / タブ」の3段階で結合する `jraResultJoinRowItems()` を新設。閾値は経験則で `JRA_GAP_SPACE_RATIO` / `JRA_GAP_TAB_RATIO` 等を利用。
- 効果: 単語内の不要なタブ挿入を防止し、`発走時刻` や日付等の検出が正しく行えるようになった。
- 結果: 実機で再検証し、12レース検出（修正前0件→修正後12件）を確認。

### 診断版 V6
- 実施内容: 診断パネルを実装。抽出行数・レース開始候補・日付候補・発走時刻候補・解析ステップ別の集計・PDF全文抽出テキスト表示などを追加して、どの段階で止まったかを確認可能にした。
- 用途: 実機での再現性調査・閾値調整のためのデバッグ用。

### 8.1.0-jockey-order-waku（騎手・並び順・枠番対応。本ドキュメントで新規追記・2026-08-09時点でコード確認）
- 実施内容(コード上で確認できる範囲):
  - `jraResultCleanJockeyName()`: 騎手名先頭の見習い減量記号(▲△☆◇)を除去
  - `jraResultParseHorseFromResultLine()`: 馬番・馬名・性齢・負担重量・騎手名・タイムの位置関係から騎手名を切り出す正規表現を複数パターン用意(基本形式・枠番ありの形式・タイム欠落時のフォールバック)
  - `current.entries.sort((a,b)=>a.horse_number-b.horse_number)`: 出走馬を着順順ではなく馬番順に並べ替え(races.js側の「entries配列のi番目≒馬番(i+1)」という前提に合わせるため)
  - `defaultWakuNumber()`: 枠番がテキストとして取得できない場合(JRA PDFは枠番を色付きアイコンで表現することが多い)に、出走頭数から`races.js`と同じロジックで簡易な枠番初期値を計算するフォールバックを追加
  - `jraResultParsePayoutLine()`の`carryState`: 複勝・ワイドのように複数行にまたがる払戻表で、2行目以降にラベル(「複勝」等)が再印字されない継続データを、「組み合わせの頭数(1頭/2頭/3頭)ごとに直前式別を保持する」方式で判定するよう改善
- **未確認事項**: 上記はいずれもコードの実装状況から確認したものであり、実機(実ブラウザ)での動作再検証の記録がドキュメント上に見当たらない。次回PDFインポートを実機で試す際は、①騎手名が正しく抽出されるか、②出走馬一覧が馬番順で表示されるか、③枠番未取得時にフォールバック値が入るか、④複勝・ワイドの複数的中が過不足なく取り込まれるか、の4点を重点的に確認し、結果をこのドキュメントに追記すること

## 5. 実装の主要技術要点（抜粋）
- 行内結合の改善（gapjoin）の考え方:
  - 直前要素の右端から今回要素の左端までの距離を直前要素の文字幅で割った比率で判定。
  - 閾値下：連結（何も挿入しない）→ 単語内とみなす。
  - 中間：半角スペースを挿入 → 単語間。
  - 閾値上：タブを挿入 → 表の列区切り。
- テキスト正規化:
  - NFKC 正規化により互換漢字・互換記号を正規化。
  - コロン等のバリエーションを正規表現で許容（`[:：]`）。
- 払戻解析の安定化:
  - 3列グリッドの払戻表を、組み合わせの「頭数ごと」で直前式別を保持して解析（carryState = {1:..., 2:..., 3:...}）。**(8.1.0で実装確認済み)**
- 馬情報抽出:
  - 出走馬行から馬番・馬名・性齢・負担重量・騎手名を抽出。見習い印の除去処理を追加。**(8.1.0で実装確認済み)**
  - entries を馬番昇順にソートして UI 前提に合わせる。**(8.1.0で実装確認済み)**
  - 枠番未取得時のフォールバック計算(`defaultWakuNumber`)。**(8.1.0で実装確認済み・新規追記)**
