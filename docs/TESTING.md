# 手動テストチェックリスト

機能追加・修正のたびに、関係する項目を確認してください。
このファイルは恒久的なチェックリストです。新しい機能を追加したら、対応する項目をここに追記してください。

## 0. セットアップ

新規ローカルDBの場合:

```bash
npx wrangler d1 execute keiba-yosou-db --local --file=./schema.sql
```

既存ローカルDBを最新版へ更新する場合:

```bash
npx wrangler d1 execute keiba-yosou-db --local --file=./latest1.sql
```

ローカル起動:

```bash
npx wrangler pages dev public
```

## 1. CSVインポート

- 購入履歴 → CSVインポート
- 同じCSVを2回実行する
  - 1回目: レスポンスの `imported > 0`
  - 2回目: レスポンスの `skipped > 0`(重複を検知して取り込まない)
- 購入履歴に取込結果が表示されること
- 的中していない買い目も「未確定」ではなく「確定(払戻¥0)」表示になること
- CSV取込した購入履歴を削除できること(削除に失敗しないこと)
- 購入履歴に紐づくレースを削除すると、購入履歴側からもきちんと消えること
  (削除後、同じCSVを再取込した際に正しく取り込まれる=重複スキップにならないこと)

API確認:

```text
GET /api/ticket-imports
```

レスポンスが `{ ok: true, items: [...] }` の形式であること。

```text
POST /api/ticket-imports
```

`multipart/form-data` の `file` フィールドにCSVファイルを指定して取込めること。

- `sample/20260719_tohyo.csv`をインポートし、以下を確認する
  - 福島4Rのワイド(BOX・ながし)で、1行に複数の的中組み合わせがある場合に、
    組み合わせごとに正しい払戻金額が計上されること(合計が払戻金額列と一致すること)
  - 同じ受付番号・通番が別日に存在しても、日付が異なれば重複スキップされず正しく取り込まれること
  - インポート後、レース管理画面で福島4Rを開くと、1〜3着セレクトに着順(三連単の的中組み合わせ)が
    自動入力されていること
  - 同じくレース管理画面の払戻入力欄に、単勝・馬連・ワイド・三連複・三連単など
    複数式別の払戻レートが自動入力されていること
  - 単勝のみ的中しているレース(例: 函館6R)では、1着セレクトだけに馬番が自動入力され、
    2・3着は空のままであること

## 1.6 CSV取込データへの馬名・騎手の反映(バックフィル)

- 馬名・騎手が未登録のレースのCSVを取り込む(取込直後は`imported_ticket_items`の
  `selections`が馬番のみになっていることを想定)
- レース管理画面でそのレースの出走馬表(馬名・騎手)を登録して保存する
- 保存後、馬券履歴・集計(騎手別収支)画面で、そのCSV取込分の購入履歴にも
  馬名・騎手が反映されていること(空欄のままにならないこと)
- 既に馬名・騎手が入っている項目は、保存し直しても値が変わらない(上書きされない)こと

## 1.5 レース登録・編集

- 新規レース登録画面で、1〜3着セレクト(馬番)に値を入力して保存する
- 保存後にそのレースを編集画面で開き直し、入力した着順(1〜3着)が保持されていること
  (以前は新規登録時のみ着順が保存されず消えてしまう不具合があった)
- 出走馬表(馬名)を1件も登録していない状態でも、1〜3着セレクトに馬番を入力するだけで
  払戻金額の入力欄が表示され、入力できること
- 1着のみ入力した状態では単勝の払戻欄だけが表示され、他の式別は
  「◯着まで入力すると表示されます」という案内が出ること
- 1〜3着すべて入力すると、三連単・三連複を含む全式別の払戻欄が表示されること
- 払戻レートを入力した後に出走頭数を変更しても、既に入力した払戻レートが消えないこと
  (該当する組み合わせが変わらない式別に限る)
- 出走頭数が5〜18頭の範囲で選択できること
- 出走頭数を選択すると、各行の枠番に初期値が自動で入ること(手動で選び直せること)
- 出走頭数を変更しても、既に入力済みの枠番・馬名・騎手が保持されること
- 着順が確定しているレースの払戻入力画面で、購入件数が0件の馬券種は
  「◯点購入」の表示が出ないこと(購入がある馬券種のみ件数が表示される)

## 2. 予想印・出走馬表示

- 騎手名が馬名の下ではなく、同じ行の後ろ(横)に表示されること
- ドロップダウンで印を選択・変更する
- 変更直後に見た目(選択状態)が反映されること
- ページを再読込する
- 同じ印が表示されること
- 1頭につき印は1つまでであること(別の印を選ぶと元の印が置き換わること、「−」で解除できること)
- 選択肢に「◎○▲△☆消」の6種類が表示されること(印なしの選択肢は「−」とだけ表示され、
  「(印なし)」という補足文言は付かないこと)
- 該当レースの購入馬券(買い目・購入金額・払戻金額)が一覧表示されること
  (出走馬表が未登録のレースでも、馬番ベースで表示されること)
- 購入馬券の取得に失敗しても、印の保存・「このレースの馬券を購入」への遷移に影響しないこと

## 2.5 予想登録画面のレイアウト

- ヘッダーの表示順が「日付・競馬場名・レース番号・レース名・頭数」の順になっていること
- 画面を開いた直後、スクロールしなくても「このレースの馬券を購入」ボタンが見えること
  (出走頭数が多いレースで確認)
- 馬一覧が購入済み馬券一覧より上に表示されること
- 競馬場名のセレクトを変更すると、ページ遷移(リロード)せずに、同じ開催日の
  別競馬場の同一レース番号(無ければ最若番)のレースへ切り替わること
- レース番号のセレクトを変更すると、同じ開催日・同じ競馬場の別レースへ切り替わること
- セレクトでレースを切り替えた後、URLの`?race=`パラメータも切り替え先のレースIDに
  更新されること(ページを再読み込みしても同じレースが表示される)
- レースを切り替えると、予想印・購入済み馬券一覧もその切り替え先のレースのものに
  更新されること

## 4.2 三連複・三連単「2頭軸」のUI(JRA/netkeiba風)

- 三連複または三連単で「2頭軸」を選ぶと、1つの馬番リストの中に「軸」「相手」の
  チェック列が並ぶこと(「軸馬①」「軸馬②」「相手」の3つの縦リストではないこと)
- 「軸」チェックは2頭まで選択できること。既に2頭選択済みの状態で他の馬の「軸」
  チェックボックスをクリックしても選択できない(無効化されている)こと
- ある馬を「軸」にチェックすると、その馬の「相手」チェックボックスは無効化されること
  (「相手」を先にチェックしていた場合は解除されること)
- 「軸」のチェックを外すと、その馬は再び「相手」として選択できるようになること
- 生成される買い目数が、以前の3リスト構成の時と変わらないこと(4章の確認項目と重複するが、
  UI変更後も購入自体が正しく行えることを確認する)

## 4.5 レース確定後の購入表示(結果確定済ラベル)

- 着順(1〜3着)または払戻レートを登録済みのレースについて、
  予想画面の「このレースの馬券を購入」ボタンが「結果確定済(購入する)」という表示に変わり、
  見た目も変化すること(ただしクリックはでき、購入ページへ遷移できること)
- 確定済みレースのURL(`buy.html?race=...`)に直接アクセスした場合、
  「着順または払戻が確定しています」という案内バナーが表示されるが、
  購入UI自体は表示され、通常通り購入できること
- `POST /api/tickets/bulk`を確定済みレースのrace_idで直接叩いても、
  拒否されず購入が成功すること(2026-07-30に方針転換。以前は409エラーで拒否していた)
- 着順・払戻が確定済みのレースに紐づく購入履歴でも、購入履歴画面から購入額・払戻・メモの
  編集、および削除ができること(2026-07-31にロック仕様を全面撤廃。以前は409エラーで
  拒否していた)。`PUT /api/tickets/:id`・`DELETE /api/tickets/:id`を確定済みの
  チケットIDに対して直接叩いても、拒否されず成功すること

## 5. 集計(stats)

- 未確定(払戻未入力)の買い目も、購入時点で支払い済みとして収支・回収率の分母に含まれること
  (未確定分が残っている間は収支が実質マイナス表示になることを確認)
- 払戻を確定すると、収支・回収率がプラス方向へ補正されること
- 着順のみ確定(払戻レート未入力)のレースが的中率の分母に含まれること
- 着順・払戻ともに未確定のレースは的中率の分母に含まれないこと
- レース別収支タブの初期表示が、日付・競馬場・レース番号の順にソートされていること
- レース別・競馬場別・騎手別のいずれも、「購入」「払戻(確定)」「収支」「回収率」「的中率」の
  列見出しをクリックすると、その列で降順にソートされること
- 同じ列見出しをもう一度クリックすると、昇順に切り替わること
- 回収率・的中率が未確定(-表示)の行は、ソート方向によらず常に末尾に表示されること
- 先頭列(レース別は「レース」、競馬場別は「競馬場」、騎手別は「騎手」)をクリックすると、
  それぞれ日付順・名前順にソートされること

## 6. マイグレーション整合性

- 新規DBは `schema.sql` の1回実行で最新版になること
- 既存DBは `latest1.sql` の1回実行で最新版になること
- 番号付きmigration(`archive/migrations/`)は通常のセットアップ・更新で使用しないこと

## 7. レース管理画面のレイアウト

- 開催日を開くと、競馬場が横並びのカラムで表示され、各カラムの下にR1〜12が並ぶこと
  (馬券購入ページのカレンダー選択後と同じ配置)
- 未登録のレース番号は「未登録」のプレースホルダー行として表示されること
- ヘッダーナビは全画面共通で「馬券購入/馬券履歴/集計/レース管理」の4タブが表示されること
  (レース管理画面だけタブが変わったりしない)
- レース一覧の各行(アコーディオン内)に「馬券購入」ボタンが無いこと
  (一般ユーザー向け画面への遷移は、ヘッダーナビの「馬券購入」タブからのみ行う)
- ページ上部にカレンダーが表示され、レースが登録されている日にマークが付くこと
  (マークには「結果確定数/レース数」が表示されること)
- カレンダーで日付をクリックすると、その日のレースだけに一覧が絞り込まれること
- 「選択解除」でカレンダーの選択が解除され、全日付の一覧表示に戻ること

## 8. 購入履歴のカレンダー表示

- ページを開いた直後からカレンダーが表示されていること(「日付から選ぶ」ボタンは無いこと)
- 初期表示ではサマリー(総購入・総払戻・収支・回収率)とカレンダーのみが表示され、
  購入履歴の詳細(レースごとの一覧)は表示されないこと。代わりに
  「カレンダーから日付を選ぶと〜」という案内文が表示されること
- 購入のある日に、その日の収支(千円単位、プラスは緑・マイナスは赤)が表示されること
- 日付をクリックすると、その日の購入履歴だけが詳細として表示されること
  (サマリーの数値は選択日にかかわらず全期間のままであること)
- もう一度同じ日付をクリック、または「選択解除」でフィルタが解除され、
  初期状態(詳細非表示)に戻ること
- 前月・翌月・今日ボタンで月を移動できること
