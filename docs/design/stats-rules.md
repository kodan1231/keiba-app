# 集計ルール

- **収支・回収率**: 未確定(払戻未入力)の買い目も、購入した時点で金額を支払い済みとして
  分母(収支の減算対象・回収率の分母)に含める。実際の財布・口座残高のイメージであり、
  結果が出るまでは実質マイナス表示になるのは意図的な仕様(README「収支・回収率の考え方」参照)。
  ```
  収支   = 総払戻金額(確定分) − 総購入金額(未確定を含む全体)
  回収率 = 総払戻金額(確定分) ÷ 総購入金額(未確定を含む全体) × 100
  ```
- **コース別収支**: 「競馬場 × コース種別(芝/ダート/障害) × 距離」でまとめる。判定に使う
  `race_course_type` / `race_distance` は `GET /api/tickets`(レースをJOIN)・
  `GET /api/ticket-imports`(`races` を全件1回SELECTしてメモリ照合。`race_id IN (...)` は
  D1 の1クエリ100バインドパラメータ上限に触れるため使わない)が付与する。
  レースに `course_type` 未登録の購入・レガシー取込は「(競馬場) コース未登録」に集約する。
  収支・回収率・的中率の計算式は他の集計表と同じ(`computeGroupStats`)。
- **総合成績タブの購入比率バー**: 購入金額の比率を「馬券種別別 / 競馬場別 / 騎手別」の
  3種類の棒グラフで表示する(`renderRatioBreakdowns()`)。分母はいずれも「全購入の合計金額
  (未確定を含む)」。騎手別は1枚に複数騎手が絡む場合、各騎手へ全額を計上する(按分しない=
  「騎手別収支」表と同じ方針)ため、バーの合計は 100% を超えうる。騎手別は金額の多い順に
  上位10名 + 「その他(N名)」に集約する。画面仕様の詳細は `screens.md` 「集計画面」参照。
- **的中率**: レース単位で、着順(`races.finish_order`)または払戻(`races.payouts`)の
  いずれかが確定していれば判定対象(分母)に含める(判定方法は上記「払戻確定バッジ・的中率
  集計の判定」参照)。着順のみ確定していて払戻レートが未入力の場合、購入履歴側の`payout`は
  まだ設定されないため「不的中」側として扱われる(組み合わせと着順を照合した厳密な的中判定は
  していない)。判定には`GET /api/tickets`が返す`race_finish_order`/`race_payouts`
  (レースをJOINして付与)を使用する。**`GET /api/ticket-imports`が返すCSVインポート分の
  アイテムにはこれらのフィールドが含まれていない点に注意(上記「CSV取込の仕様」の
  「集計への反映漏れ」参照)**。なお、CSVインポート分の`payout`は常に確定値(`null`に
  ならない)のため、的中率集計上「レース結果は確定しているのに判定対象から漏れる」ケースは
  CSVインポート分の範囲では発生しない(引き続き`race_finish_order`/`race_payouts`欠落自体は
  残る)
