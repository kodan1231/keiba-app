# データ検索画面「重賞検索」タブ(2026-10-02追加)

重賞レースを1つ選ぶと、次の3つを1画面で見られるタブ。

1. **今年の出走馬一覧**(未発表・未取込なら「未発表(未取込)」)
2. **出走馬ごとの詳細**(過去5走・血統・持ちタイム・着別度数等。新聞の馬柱に相当)
3. **その重賞の過去10年の成績**と傾向集計

- 画面: `public/data-search.html`(`data-panel="graded-race"`)/ `public/graded-race-search.js`(`gr*`)
- API: `functions/api/data-search/graded-races.js` / `graded-race.js` / `graded-race-horses.js`
- 共通ロジック: `functions/api/_lib/graded-race-search.js`(脚質判定・タイム換算・着別度数の加算等。DB不使用)

## 前提・方針(ユーザー確認済み)

- 外部サイトからの自動取得は行わない(血統等の既存netkeiba連携〈`horses`〉のみ流用)。
  データはすべて自アプリに取り込み済みのもの(`races` / `race_results` / `horses`)から作る
- 今年の出走馬は、出走馬一覧PDFを手動で取り込んだ後に表示される。特別登録段階は対象外
- 過去年の結果は、JRA公式の過去レース結果ページ(`JRADB/accessS.html`)を
  既存のユーザースクリプトで1レースずつ取り込む運用で補完する(実機で取り込めることを
  ユーザー確認済み)。新規の取込経路は作らない
- 取り込まれていないデータは**表示しない**(「未取込」といった欠損表示もしない)。
  過去5走は「取り込み済みのレースの中での直近5走」になる
- 障害重賞も対象に含める
- レース名が変わった重賞は別レースとして扱う(名寄せはしない。
  既存の`gradedRaceNameKey()`による突き合わせのみ)

## 画面(`data-search.html` に `data-panel="graded-race"` を追加)

- タブ名「重賞検索」。既存の「レース成績」「馬情報検索」と同列に並べる
- 閲覧は全ログインユーザー可(`requireAdmin` しない。既存のデータ検索APIと同じ扱い)

### 重賞の選択

- 文字入力欄+候補リスト。入力文字で部分一致の絞り込みを行う
  (比較は `gradedRaceNameKey()` 相当の正規化後。「ステークス」と「S」の違いを吸収する)
- グレード絞り込みチップ:「すべて / G1 / G2 / G3 / 障害」
- 候補は `graded_races` の開催日(月日)順。月ごとの見出しで区切る。
  各候補に「グレード・競馬場・芝ダ距離・年齢条件」を併記する
- 開催日未設定の行は末尾にまとめる(「開催日未設定」見出し)
- 重賞を選ぶと候補一覧は隠れ、詳細を表示する。「← 重賞一覧に戻る」で候補一覧へ戻る
- 漢字のレース名をカナで入力しても一致しない(読みのデータは持たない)

### ① 今年の出走馬一覧

「今年」は日本時間の現在年。

| 状態 | 判定 | 表示 |
|---|---|---|
| 未発表(未取込) | 今年の該当レースが `races` に無い、または `entries` が0頭 | 「未発表(未取込)」+ 開催予定日 |
| 出走馬確定 | 該当レースがあり、着順未確定 | 出走馬一覧 |
| 終了 | 該当レースの着順確定済み | 出走馬一覧(着順・人気・タイムの列を追加) |

一覧の列: 枠 / 馬番 / 馬名 / 性齢 / 斤量 / 騎手 / 調教師 / 父 / 母父 / 前走(着順・レース名)/
間隔 / 脚質 / 持ちタイム(同芝ダ・同距離)

- 取消・除外は予想登録画面と同じ扱い(結果取込後に `race_results.status` で状態ラベルを表示)
- 行を開くと、②の出走馬の詳細を表示する。表示は予想登録画面の「過去成績」の部品を流用する

### ② 出走馬ごとの詳細

| 項目 | 内容・定義 |
|---|---|
| 基本情報 | 性齢・斤量・騎手・調教師・馬主・生産牧場 |
| 血統 | 父・母・母父(`horses`。未取得の馬は画面側から1頭ずつ順に既存の `GET /api/data-search/horse-info` を呼んで取得する。一度取得した馬は再取得しない) |
| 過去5走 | 取り込み済みの直近5走。`race_results` の取込項目を全部出す(日付・競馬場・レース名・芝ダ距離・馬場・天候・頭数・馬番・枠番・人気・着順・騎手・斤量・タイム・着差・通過順・上り・馬体重〈増減〉・競走中の出来事)。「全戦績を表示」で全件を開閉する |
| 持ちタイム(同距離) | 今回と同じ芝ダ・同じ距離での最速タイム(競馬場は問わない) |
| 持ちタイム(同コース) | 今回と同じ競馬場・同じ芝ダ・同じ距離での最速タイム |
| 上り最速 | 全体での最速、および今回と同じ芝ダでの最速 |
| 着別度数 | 「1着-2着-3着-着外」の形で、次の区分ごとに出す。全体 / 芝・ダート・障害別 / 今回の距離(同芝ダ)/ 今回の競馬場(同芝ダ)/ 今回のコース(場・芝ダ・距離)/ 馬場状態別(良・稍重・重・不良。同芝ダ)/ 重賞 / この重賞 |
| 前走からの間隔 | 前走日から今回の開催日までの日数を7で割って四捨五入し、1なら「連闘」、それ以外は「中(週数−1)週」 |
| 前走の馬体重 | 馬体重と増減 |
| 脚質 | 下記「脚質の判定」 |
| 騎手のコース成績 | 今回の騎手の、今回のコース(場・芝ダ・距離)での着別度数・勝率・複勝率(対象レースより前の、`race_results` が取り込み済みのレースのみ。`finish_order` しか無いレースは数えない) |
| 騎手とこの馬の成績 | 今回の騎手がこの馬に乗った時の着別度数 |

持ちタイムと上り最速には、タイムに加えて「日付・競馬場・レース名・馬場状態・着順」を付ける。
一覧の「持ちタイム(同距離)」列にはタイムと馬場状態を出す。

過去走・着別度数等の集計対象は、**対象レースの開催日より前**の走のみ(過去の年の重賞を
表示した場合でも、その時点での「過去走」になる)。

**集計対象の共通ルール**
- 着別度数・持ちタイム・上り最速の対象は `status='finished'` の走のみ
- 中止(`stopped`)は着別度数だけ「着外」に数える
- 取消・除外は数えない
- タイムは `time_text`("1:25.0" 等)を秒に換算して比較する
- 障害も同じルールで扱う。平地と障害で距離が重なることは実運用上ない前提

#### 脚質の判定

1. 各走の `corner_positions`("3-3-2-1" 等)の最初の数値を、その走の頭数で割る
2. 値に応じて次のように判定する
   - 1番手:逃げ
   - 頭数の3分の1以下:先行
   - 頭数の3分の2以下:差し
   - それより後ろ:追込
3. 直近5走で最も多い脚質をその馬の脚質とする。同数の場合は、より最近の走の脚質を採用する
4. 通過順が無い走は判定対象から外す(直線1000m、またはスマホ版結果HTMLから取り込んだ走)
5. 判定できる走が0件なら脚質は空欄にする

### ③ この重賞の過去成績(10年分)

- 対象は**今年を除く直近10年**。今年が終了済みの場合、今年分は①に結果込みで表示するため、③には含めない
- 年ごとにカードを並べる(新しい年から)。取り込みが無い年は出さない
- カードに表示するもの
  - 開催日・競馬場・芝ダ距離・馬場・天候・頭数
  - 1〜3着の馬番・馬名・性齢・人気・騎手・斤量・タイム・着差・上り・通過順・脚質
  - 主要な払戻:単勝・馬連・3連単
  - 開催場所や距離が今年と異なる年には印を付ける(改修工事による代替開催などのため)
- カードを開くと、全着順(`race_results` の全項目)と全券種の払戻を表示する
- `race_results` が無く `races.finish_order` しか無い年(CSV取込のみ等)は、
  1〜3着(`entries` の馬名)と払戻だけを表示する

#### 傾向集計(取り込み済みの年だけで集計)

- 人気別・枠番別・年齢/性別・脚質別は、**全着順(`race_results`)がある年だけ**で集計する
  (`finish_order` しか無い年は母数〈着外馬〉が分からないため除外)
- 払戻の統計は、払戻が登録されている年すべてで集計する
- 枠番は `race_results.waku_number`、無ければ `races.entries` の同じ馬番の枠番を使う

見出しに「過去10年のうちN年分を集計」と表示する。

- 人気別成績(1・2・3番人気、4〜6、7〜9、10番人気以下):着別度数・勝率・複勝率
- 枠番別成績(1〜8枠):着別度数・勝率・複勝率
- 年齢別・性別の成績
- 脚質別成績(上記の判定ルールで、その年のその馬について判定)
- 単勝・馬連・3連単の払戻金額の平均・最大・最小
- 勝ちタイム・勝ち馬の上りの平均(今年と同じ競馬場・同じ距離の年のみ対象)

### API(すべてGET・ログインユーザー全員が閲覧可)

| API | 内容 |
|---|---|
| `GET /api/data-search/graded-races` | 重賞の候補一覧(`graded_races` 全件。年間140件前後の小さいマスタのため全件SELECT) |
| `GET /api/data-search/graded-race?id=<graded_races.id>` | ①の判定結果・出走馬、③の過去10年分(全着順・払戻)と傾向集計 |
| `GET /api/data-search/graded-race-horses?race_id=<races.id>` | ②の全項目(出走各馬の全戦績と集計値、`horses` にある血統等) |

### サーバー処理の方針(D1の行数上限・サブリクエスト上限への対策)

- **対象レースの特定**
  - `races` は直接SELECTせず、`races_cache`(`getAllRacesRaw`)をメモリ上で走査する
  - `gradedRaceNameKey(race_name) === graded_races.name_key` のレースを年ごとに拾う
  - 新しいインデックスは追加しない
- **③の結果取得**
  - `race_results WHERE race_id IN (…)` で取得する
  - IN句の件数は最大11件(今年1件+過去10年。同じ年に同名レースが複数ある異常データでも十数件程度)で、100件の上限には届かない
- **②の戦績取得**
  - `race_results WHERE horse_key IN (…)` で出走全馬の全戦績を1クエリで取得する
  - 検索キーは `horse-history.js` と同じく「正規化した馬名キー+`horse_aliases` の逆引きキー」にする
  - IN句の件数は「出走頭数(最大18)×(1+その馬のエイリアス数)」で、実質20〜30件程度
  - 保険として90件ずつのチャンク分割を入れる(CLAUDE.md の不変条件)
  - 検索キーを組み立てる処理は `horse-history.js` から `_lib/horse-alias.js` へ切り出して共用する
- **各走のレース情報と頭数**
  - レース情報(日付・場・芝ダ距離・馬場・天候・レース名)は `races_cache` から引く
  - 頭数は `race_stats_cache`(`getRaceResultsGroupedByRaceId`)から数える。追加のクエリは発行しない
- **騎手のコース成績**
  - `races_cache` と `race_stats_cache` をメモリ上で突き合わせて集計する(`race-stats.js` と同じ考え方)
  - 騎手名の突き合わせキーは `race-stats.js` の `jockeyKey` に合わせる
- **重賞判定(「重賞」区分の着別度数)**
  - `loadGradedRaceMap` + `classifyRace` で判定する
- **netkeibaからの血統取得**
  - サーバー側でまとめて行わない(18頭分だと外部アクセス上限の50回を超えるため)
  - 未取得の馬だけ、画面側から既存APIを1頭ずつ順番に呼ぶ
- **書き込み**
  - 本タブのAPIは読み取りのみ。キャッシュ保存も新設しない

## 運用上の注意・副作用

- **過去年の取込で `races` が増える**:10年分で約1,400レース増える
  - `GET /api/races` の全件レスポンスを読む予想登録画面・レース管理画面の通信量が増える
  - 予想登録画面は1件を探すためだけに全件を読んでいる。重くなったら `GET /api/races/:id` へ切り替える(本タスクの範囲外)
- **データ検索「レース成績」タブの集計に過去の重賞が混ざる**:過去年の重賞結果を取り込むと、平均配当や騎手ランキングの母数に含まれる
- **D1の書き込み上限**
  - 1レース分の結果取込で、インデックス込みで100行前後の書き込みになる
  - 10年分を一気に取り込むと1日の上限(10万行)を超えうる
  - 1日に取り込むのは数百レース程度までにする
- **脚質が出ない走がある**:スマホ版の結果HTMLから取り込んだレースには通過順が無いため、脚質判定の対象外になる
