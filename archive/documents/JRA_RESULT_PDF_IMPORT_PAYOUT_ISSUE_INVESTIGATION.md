# JRAレース結果PDFインポート(払戻取込)が0レースになる不具合 調査・修正記録

**ステータス: 0レース問題は実機で解消を確認済み。①騎手抽出は実機確認済み。 ②並び順・③枠番・④払戻の一部欠落は実装・Node単体テストまで完了(構文チェック
済み、実機再検証は次回持ち越し)。**

このドキュメントは `docs/JRA_RESULT_PDF_IMPORT_FIX_V3〜V5.md` 等と同様の
「修正記録」。①②③④すべての実機再検証をもって完了とする(末尾「この調査記録の
使い方」参照)。

## 症状(2026-08-05報告)

`races.html` の「JRAレース結果PDFをインポート」から実際のJRA公式サイトの
「レース結果一覧」PDFを取り込むと、解析結果が **0レース** になる。

## 原因(実機診断ログにより確定・2026-08-06)

ユーザーから実ブラウザでの診断パネルの実測値を共有してもらい、原因を確定した。

| 項目 | 実測値 | 意味 |
|---|---|---|
| 抽出行数 | 615 | PDF.js自体のテキスト抽出は正常 |
| 発走時刻候補 | 13 | 「N時M分」パターンは検出できていた |
| 「発走時刻」候補 | **0** | 「発走」+「時刻」という文字列が1件も検出できない |
| 日付候補 | **0** | 「2026年8月2日」のような日付パターンも0件 |
| 開催情報候補 | **0** | 「2回中京4日」のような開催情報パターンも0件 |

「時」「分」のような1〜2文字の隣接パターンは検出できるのに、「発走」「時刻」の
ような**単語をまたぐ文字列**が軒並み検出できていないことから、行内テキストの
連結方法に問題があると特定した。

`public/jra-result-pdf.js` の `jraResultExtractPdfPages()` は、PDF.jsが返す
個々のテキスト断片を同一行(Y座標が近い)ごとにグルーピングしたあと、

```js
text: r.items.sort((a,b)=>a.x-b.x).map(x=>x.str).join("\t"),
```

のように、**間隔の大小を一切見ずに一律タブ文字で連結**していた。JRA公式PDFの
ような表形式で几帳面に組版されたPDFでは、1文字・1単語ごとに別々のテキスト
オブジェクトとして配置されていることが多く、この場合「発」と「走」の間、
「２０２６」と「年」の間のような、**本来隙間なく続く1つの単語の内部**にも
タブが挿入されてしまう。

一方、`jraResultIsStartLabel()`(`発走\s*時刻`)、`jraResultFindMeeting()`
(`(\d{4})年...`、`(\d+)回(競馬場)(\d+)日`)などの正規表現は、文字同士が
隙間なく連続していることを前提に書かれていたため、間にタブが挟まると
軒並み不一致になっていた。時刻検出(`\d{1,2}\s*時\s*\d{1,2}\s*分`)だけは
たまたま全ての区切りに`\s*`を入れていたため、唯一検出できていた。

なお、`docs/JRA_RESULT_PDF_IMPORT_FIX_V3.md`〜`_V5.md`・`_DIAGNOSTIC_V6.md`・
`_VALIDATION.md`に記載された過去の「検証済み」は、実ブラウザのPDF.js抽出結果
ではなく、手作業でシミュレーションしたテキストに対する検証だったため、
この実PDF特有の挙動を見逃していた。

## 修正方針・実装内容(2026-08-06承認・実装済み)

**方針A: 行結合時のタブ一律連結をやめ、実際の間隔(ギャップ)を計測して
「連結/スペース/タブ」の3段階に振り分ける** 方式を採用した(承認済み)。

`jraResultJoinRowItems()` を新設し、直前のテキスト要素の右端から今回の要素の
左端までの実測ギャップを、直前要素の文字幅に対する比率で判定する。

- 隙間がごく小さい(同一単語内の文字とみなせる) → 連結(区切り文字なし)
- 隙間が単語区切り相当 → 半角スペースで連結
- 隙間が列区切り相当(表組みのセル間など) → タブで連結(表構造の解析を維持するため)

これにより「発走時刻」のような単語は正しく1つの文字列として復元され、
`\s*`を使った既存の正規表現もそのまま機能する。表組み(払戻表等)の列区切りは
引き続きタブとして区別されるため、既存の表構造解析ロジックへの影響を避けている。

あわせて、以下の主要な検出関数には**保険として**単語内にも`\s*`を許容する
形に変更した(閾値調整の余地や、フォントによる微妙な間隔差に対する保険)。

- `jraResultParseDate` / `jraResultFindMeeting` / `jraResultFindMeetingLoose`
  (年月日・開催回のパターン)
- `jraResultIsStartLabel`(「発走時刻」)
- `jraResultParseCourseLoose` / `jraResultParseCourse`(「コース」「メ��トル」)
- ヘッダー復元時の「本賞金」検出

閾値(`JRA_GAP_SPACE_RATIO` / `JRA_GAP_TAB_RATIO` 等)は経験則による仮の値であり、
実機での再検証時にずれが見つかれば調整が必要になる可能性がある。そのため、
診断パネルに新しく「行内文字間隔サンプル・閾値調整用」というセクションを追加し、
各行を構成するテキスト断片間の実測ギャップと、連結/SPACE/TABどれと判定したかを
確認できるようにした(`jraResultRenderDiagnostics()`).

パーサーバージョンは `7.0.0-diagnostic` → `8.0.0-gapjoin` に更新し、
診断パネルの見出しで区別できるようにした。
