# 馬券帳 - 疑似馬券購入シミュレーター

Cloudflare Pages + Pages Functions + D1 で動く、無料で使える疑似馬券購入・収支管理アプリです。
単勝・複勝・枠連・馬連・ワイド・馬単・三連複・三連単、および通常・ボックス・流し・フォーメーションの
購入方式に対応しています。PC・スマホどちらからもアクセスできます。

## ページ構成(メニュー順)

1. **馬券購入** (`buy.html`) : 日付→競馬場×Rの一覧表からレースを選び、出走馬をタップ(または馬番を直接入力)して購入を記録。組み合わせごとに個別の金額を設定可能
2. **購入履歴** (`index.html`) : 登録した購入をレース別・購入グループ別に一覧表示(読み取り専用。払戻入力はレース管理で行う)
3. **集計** (`stats.html`) : 総合成績、レース別・競馬場別・騎手別の収支・回収率・的中率
4. **レース管理** (`races.html`) : 出走馬表の登録・編集、開催日程の一括登録、払戻金額の入力

## 主な機能

- **日付起点のレース選択**: 日付を選ぶと、その日に登録済みのレースが競馬場×Rの一覧表で表示されます
- **出走馬の自動紐付け**: レースを登録しておけば、購入時は馬番をタップするだけで枠・馬名・騎手が自動で入る
- **レース未登録でも購入可能**: 出走馬が未登録のレースでも、馬番を直接入力して購入できます(あとからレース管理で馬名・騎手を追記可能)
- **組み合わせごとの個別金額**: ボックス・流し・フォーメーションで生成された組み合わせは、一括金額を設定したうえで個別に金額を上書きできます
- **開催日程の一括登録**: JRA公式サイト等からコピーした「日付・競馬場」のテキストを貼り付けると、1〜12Rの空レース枠をまとめて作成します
- **出走馬情報の一括入力**: netkeiba等からコピーした「馬番・馬名・騎手」のテキストを貼り付けると、出走馬の入力欄に自動反映します(読み取り結果は必ず保存前に確認・修正できます)
- **払戻金額の一括入力**: レース編集画面で、そのレースに紐づく全ての購入グループの払戻金額をまとめて入力できます
- **的中率**: クラブJRA-netと同じ考え方(レース単位。1レースでいずれかの馬券が的中していれば「的中」)で算出します

### 収支・回収率の考え方

未確定(払戻未入力)の馬券も、購入した時点で金額を支払い済みとして収支に反映します。

```
収支   = 総払戻金額(確定分) − 総購入金額(未確定を含む全体)
回収率 = 総払戻金額(確定分) ÷ 総購入金額(未確定を含む全体) × 100
```

結果が出るまでは実質マイナス表示になりますが、これは意図的な仕様です(まだ結果が出ていない
分は「捨てたお金」として一旦計上し、払戻が確定するごとにプラス方向に補正されていくイメージです)。

### 「自動化」について

JRA公式サイトやnetkeibaへの**プログラムによる自動アクセス(スクレイピング)は行っていません**。
利用規約上の懸念があるためです。そのかわり、ユーザー自身がコピーしたテキストを貼り付けると
自動で解析・入力される機能(開催日程・出走馬情報)を用意し、手打ちの手間を減らしています。
解析結果は必ず画面上で確認・修正してから保存する設計です。

## 構成

```
public/
  buy.html / buy.js         ... 馬券購入(レース選択・組み合わせ生成・個別金額)
  index.html / app.js       ... 購入履歴一覧(グループ表示・読み取り専用)
  stats.html / stats.js     ... 集計(収支・回収率・的中率)
  races.html / races.js     ... レース管理(出走馬表・開催日程一括登録・払戻入力)
  auth.js                   ... 全ページ共通のログイン/ログアウト処理
  bettypes.js                ... 馬券種類・購入方式の定義(共通)
  combos.js                  ... 組み合わせ生成ロジック(ボックス/流し/フォーメーション)
  parse.js                   ... テキスト貼り付けの解析ロジック(開催日程・出走馬情報)
functions/
  _middleware.js             ... 認証チェック
  api/auth/                  ... ログイン/ログアウト/認証確認
  api/races/                 ... レースの一覧・登録・編集・削除・一括登録(bulk)
  api/tickets/                ... 購入履歴の一覧・一括登録(bulk・組み合わせごとの金額対応)・払戻更新・削除
schema.sql                   ... D1データベースの最新版テーブル定義(新規セットアップ用)
latest1.sql                  ... 既存DBを最新版(v10相当)へ更新する統合マイグレーション
archive/migrations/          ... 過去の番号付きmigration(v2～v10)のアーカイブ(通常は実行しない)
docs/DESIGN.md                ... データ構造・データフロー・集計ルールなどの設計方針(生きたドキュメント)
docs/TESTING.md                ... 手動テストチェックリスト(生きたドキュメント)
docs/BACKLOG.md                 ... 承認済みだが未実装のタスクの引継ぎメモ
wrangler.toml
```

このREADME、`docs/DESIGN.md`、`docs/TESTING.md`はいずれも常に現状を反映する
「生きたドキュメント」として管理します。過去の作業ログ・修正メモの類は
ファイルとして残さず、コミットメッセージ側に記録する方針です。
`docs/BACKLOG.md`のみ例外で、「現状」ではなく「承認済みだが未着手のタスク」を
引き継ぐためのドキュメントです。着手時に該当項目を削除し、他の生きたドキュメントへ反映します。

## データの考え方

- `races`テーブル: レースの出走馬表を保持。出走馬が空(`entries: []`)のまま保存することもできる
- `tickets`テーブル: 購入した馬券の**組み合わせ1点ごとに1行**。同じ購入操作(ボックス等)で生成された
  組み合わせは同じ`group_id`でまとめられる。金額(`amount`)は組み合わせごとに個別に持つ
- 払戻金額はレース管理画面で、レースに紐づく全購入グループをまとめて入力する
- 騎手別の収支は、1枚の馬券に複数騎手が関わる場合、関係する騎手それぞれに購入金額・払戻金の**全額**を
  計上する(按分しない)。そのため騎手別の合計は購入履歴全体の合計と一致しない

## DBマイグレーション方針

DBスキーマは最新版を基準に管理します。

- **新規DBの構築**: `schema.sql` を1回実行します。
- **既存DBの最新版への更新**: `latest1.sql` を1回実行します。
- `migrate_v2.sql` ～ `migrate_v10.sql` は過去の変更履歴として `archive/migrations/` に保管しています。通常のセットアップ・更新では使用しません。

`latest1.sql` は、番号付きmigrationを順番に適用した結果の最終状態(v10相当)へ既存DBを更新するための統合migrationです。

### 既存のリモートDBを最新版へ更新

```bash
npx wrangler d1 execute keiba-yosou-db --remote --file=./latest1.sql
```

### 既存のローカルDBを最新版へ更新

```bash
npx wrangler d1 execute keiba-yosou-db --local --file=./latest1.sql
```

更新後に再デプロイします。

```bash
npx wrangler pages deploy public --project-name=keiba-yosou-app
```

> 注意: `latest1.sql` は既存DBを最新版へ更新するためのものです。新規DBは `schema.sql` を使用してください。
> 既存DBに `latest1.sql` のv13(複数ユーザー対応)を適用した場合は、管理者アカウント作成後に
> `assign_existing_data_to_admin.sql` を1回実行して、既存データを管理者アカウントに割り当ててください
> (下記「複数ユーザー対応について」参照)。

### 単発の追加マイグレーション(v13適用済みDB向け)

`latest1.sql`は「まっさらなDBに1回だけ実行する」累積migrationのため、既に運用中のDBに対して
繰り返し実行することはできません(DROP TABLE等が既に適用済みでエラーになります)。
v13適用後に追加された小さなスキーマ変更は、都度これとは別の単発マイグレーションファイルとして
用意します。現時点で存在するもの:

- `add_course_type_distance.sql`(2026-08-02): `races`にコース種別(`course_type`)・距離
  (`distance`)を追加。既存DBには1回だけ実行してください。

```bash
npx wrangler d1 execute keiba-yosou-db --remote --file=./add_course_type_distance.sql
```


## セットアップ手順(新規の場合)

### 1. Wranglerのインストール・ログイン

```bash
npm install -g wrangler
wrangler login
```

### 2. D1データベースを作成

```bash
wrangler d1 create keiba-yosou-db
```

実行結果に表示される `database_id` をコピーし、`wrangler.toml` の
`database_id = "ここに..."` の部分に貼り付けてください。

### 3. テーブルを作成

```bash
wrangler d1 execute keiba-yosou-db --remote --file=./schema.sql
```

`schema.sql` には、初期管理者アカウント(ユーザー名 `admin` / パスワード `password`)が
自動的に登録されます。デプロイ後、必ずログインしてパスワードを変更する運用に切り替えてください
(現時点ではアプリ内にパスワード変更機能が無いため、変更する場合はDBを直接更新してください)。

### 4. Cloudflare Pagesにデプロイ

```bash
wrangler pages deploy public --project-name=keiba-yosou-app
```

### 5. 環境変数とD1バインディングをダッシュボードで設定

Cloudflareダッシュボード → Workers & Pages → keiba-yosou-app → Settings で以下を設定:

- **Variables and secrets**:
  - `APP_PASSWORD`: 好きな文字列を設定(Secret推奨)。2026-08-01の複数ユーザー対応より、
    ログイン用パスワードとしては使われなくなり、**セッションCookieの署名用シークレット**
    として使われる。値そのものに意味は無いので、他人に推測されにくいランダムな文字列を
    設定しておけばよい
  - `ADMIN_USERNAMES`: 管理者にしたいユーザー名をカンマ区切りで設定(例: `admin` または
    `admin,papa`)。ここに載っているユーザー名でログインした人だけが、レース情報の登録・編集や
    管理画面(未登録レース一覧・登録ユーザー一覧)を利用できる
- **Bindings**: D1 database の変数名を `DB` にして `keiba-yosou-db` を紐付け

設定後、もう一度手順4のコマンドを実行すると反映されます。

### 6. 完成

発行されたURLにPC・スマホからアクセスし、ログイン画面の「新規ユーザー登録」から
ユーザーを作成してください(招待コード等は無く、URLを知っていれば誰でも登録できます)。
管理者にしたいユーザーは、登録後に上記の `ADMIN_USERNAMES` へユーザー名を追加してください。

## 複数ユーザー対応について(2026-08-01〜)

- ログイン画面から誰でも自己登録できます(ユーザー名+パスワード)。招待コードの仕組みは
  ありません
- 管理者かどうかは、Cloudflare Pagesの環境変数 `ADMIN_USERNAMES` で判定します。DBにフラグは
  持っていないため、環境変数を編集するだけで管理者を増減できます
- レース情報(日付・出走馬・着順・払戻など)は全ユーザー共有のデータで、登録・編集・削除は
  管理者のみが行えます。それ以外(購入履歴・CSVインポート履歴・予想印・予想メモ・馬メモ)は
  ユーザーごとに完全に分離されており、他のユーザーからは見えません
- CSVインポート時に該当レースがまだ登録されていない場合、以前は自動的にレースを作成して
  いましたが、レース登録が管理者限定になったことに伴い廃止しました。未登録のまま取り込まれた
  データは、管理画面(`admin.html`)の「未登録レース一覧」から確認でき、管理者がそのレースを
  登録すると自動的に紐付きます
- 個別ログイン導入前に登録されていた購入履歴・CSVインポート履歴・予想印・予想メモ・馬メモは、
  DBマイグレーション直後は「誰のものか」の情報を持たない(user_idがNULL)状態になっています。
  管理者アカウントを作成した後、`assign_existing_data_to_admin.sql` を1回実行すると、
  それらすべてが管理者アカウントの所有として割り当てられます
  ```bash
  wrangler d1 execute keiba-yosou-db --remote --file=./assign_existing_data_to_admin.sql
  ```
  (管理者のユーザー名を `admin` から変更した場合は、ファイル内の `'admin'` を実際の
  ユーザー名に書き換えてから実行してください)
- ユーザー削除機能・パスワードリセット機能は現時点では実装していません(`docs/BACKLOG.md`に
  将来タスクとして記録済み)
