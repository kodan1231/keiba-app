# 馬券帳 - 疑似馬券購入シミュレーター

**FIX ver1.0**(2026-08-10整理)

Cloudflare Pages + Pages Functions + D1 で動く、無料で使える疑似馬券購入・収支管理アプリです。
単勝・複勝・枠連・馬連・ワイド・馬単・三連複・三連単、および通常・ボックス・流し・フォーメーションの
購入方式に対応しています。PC・スマホどちらからもアクセスできます。

> **ドキュメントの読み方**: このREADME・`docs/DESIGN.md`・`docs/TESTING.md`は、
> 常に「現時点の仕様・現時点のテスト項目」だけを記す生きたドキュメントです。
> 過去の不具合修正・調査の経緯や日付単位の作業ログは持たず、`archive/documents/`
> 配下に退避しています。未着手のタスク・調査中の不具合は`docs/BACKLOG.md`を参照してください。
> JRAレース結果PDFインポート機能の詳細仕様は`docs/DESIGN.md`「JRAレース結果PDFインポート」
> 節に統合されています(独立したドキュメントは廃止しました)。

## ページ構成(メニュー順)

1. **馬券購入** (`buy.html`) : 日付→競馬場×Rの一覧表からレースを選ぶ画面。レースを選ぶと**予想登録画面(下記2)へ遷移**し、馬券購入はそこでの「このレースの馬券を購入」ボタン経由で開始する(このとき`buy.html?race=ID`にレースIDが渡り、出走馬表の一覧が直接開く)。購入時は出走馬をタップ(または馬番を直接入力)して購入を記録し、組み合わせごとに個別の金額を設定できる
2. **予想登録** (`prediction.html`。メニューには表示されず、「馬券購入」でのレース選択後に遷移) : 予想印(◎○▲△☆消。1頭1つまで)・馬メモ(馬名継続管理)の登録、購入済み馬券の確認、「このレースの馬券を購入」ボタンからの購入画面への遷移
3. **購入履歴** (`index.html`) : 登録した購入(通常購入+CSVインポート分)をレース別・購入グループ別に一覧表示(読み取り専用。払戻入力はレース管理で行う)。PCではCSVインポート機能あり(スマホでは非表示)。一般ユーザーの上部ナビには表示されない「レース管理」「管理」を除く3タブ(馬券購入・馬券履歴・集計)が表示される
4. **集計** (`stats.html`) : 総合成績、レース別・競馬場別・騎手別の収支・回収率・的中率
5. **レース管理** (`races.html`。管理者のみナビに表示) : 出走馬表の登録・編集、開催日程の一括登録、出走馬一覧PDF・JRAレース結果PDFの一括インポート、払戻金額の入力
6. **管理** (`admin.html`。管理者のみナビに表示) : CSVインポートで参照されたがまだレース登録されていない「未登録レース一覧」、登録ユーザー一覧の確認

## 主な機能

- **日付起点のレース選択**: 日付を選ぶと、その日に登録済みのレースが競馬場×Rの一覧表で表示されます
- **出走馬の自動紐付け**: レースを登録しておけば、購入時は馬番をタップするだけで枠・馬名・騎手が自動で入る
- **レース未登録でも購入可能**: 出走馬が未登録のレースでも、馬番を直接入力して購入できます(あとからレース管理で馬名・騎手を追記可能)
- **組み合わせごとの個別金額**: ボックス・流し・フォーメーションで生成された組み合わせは、一括金額を設定したうえで個別に金額を上書きできます
- **開催日程の一括登録**: JRA公式サイト等からコピーした「日付・競馬場」のテキストを貼り付けると、1〜12Rの空レース枠をまとめて作成します
- **出走馬情報の一括入力**: netkeiba等からコピーした「馬番・馬名・騎手」のテキストを貼り付けると、出走馬の入力欄に自動反映します(読み取り結果は必ず保存前に確認・修正できます)
- **出走馬一覧PDFの一括インポート**: JRA公式サイトの「出走馬一覧」PDF(枠番・馬番未確定/確定後いずれも可)を解析し、出走馬(馬名・騎手・枠番・馬番)を一括登録・更新できます。詳細は`docs/DESIGN.md`「出走馬一覧PDFインポート」参照
- **JRAレース結果PDFの一括インポート**: JRA公式サイトの「レース結果一覧」PDFを解析し、着順・払戻を一括登録できます。詳細は`docs/DESIGN.md`「JRAレース結果PDFインポート」参照
- **払戻金額の一括入力**: レース編集画面で、そのレースに紐づく全ての購入グループの払戻金額をまとめて入力できます
- **的中率**: クラブJRA-netと同じ考え方(レース単位。1レースでいずれかの馬券が的中していれば「的中」)で算出します
- **予想印・馬メモ**: 予想登録画面で、レースごとに出走馬へ予想印(◎○▲△☆消。1頭1つまで)を付けたり、馬名をキーにした継続メモ(通算成績や気づき等)を残せます
- **CSVインポート**: Club JRA-Net等からダウンロードした購入履歴CSVを取り込み、通常購入と統合して購入履歴・集計に反映できます(PCの購入履歴画面から。取込時点でレース未登録の場合は管理画面の「未登録レース一覧」に表示され、後からレースを登録すると自動的に紐付きます)
- **複数ユーザー対応**: ユーザーごとにログインでき、購入履歴・CSVインポート履歴・予想印・予想メモ・馬メモは完全に分離されます。レース情報(日付・出走馬・着順・払戻)は全ユーザー共有で、登録・編集・削除は管理者のみが行えます

### 収支・回収率の考え方

未確定(払戻未入力)の馬券も、購入した時点で金額を支払い済みとして収支に反映します。

```
収支   = 総払戻金額(確定分) − 総購入金額(未確定を含む全体)
回収率 = 総払戻金額(確定分) ÷ 総購入金額(未確定を含む全体) × 100
```

結果が出るまでは実質マイナス表示になりますが、これは意図的な仕様です(まだ結果が出ていない
分は「捨てたお金」として一旦計上し、払戻が確定するごとにプラス方向に補正されていくイメージです)。

### 「自動化」について

JRA公式サイトやnetkeibaへの**プログラムによる自動アクセス(スクレイピング)は行っていません**。
利用規約上の懸念があるためです。そのかわり、ユーザー自身がコピーしたテキスト・保存したPDFを
貼り付ける/アップロードすると自動で解析・入力される機能(開催日程・出走馬情報・レース結果)を
用意し、手打ちの手間を減らしています。解析結果は必ず画面上で確認・修正してから保存する設計です。

## データの考え方

- `races`テーブル: レースの出走馬表を保持。出走馬が空(`entries: []`)のまま保存することもできる
- `tickets`テーブル: 購入した馬券の**組み合わせ1点ごとに1行**。同じ購入操作(ボックス等)で生成された
  組み合わせは同じ`group_id`でまとめられる。金額(`amount`)は組み合わせごとに個別に持つ
- 払戻金額はレース管理画面で、レースに紐づく全購入グループをまとめて入力する
- 騎手別の収支は、1枚の馬券に複数騎手が関わる場合、関係する騎手それぞれに購入金額・払戻金の**全額**を
  計上する(按分しない)。そのため騎手別の合計は購入履歴全体の合計と一致しない

## DBマイグレーション方針

DBスキーマは最新版を基準に管理します。

**運用ルール(node不要・wranglerコマンドのみで手動運用)**
- **初期セットアップ(まっさらな新規DB)のときだけ`schema.sql`を1回実行する。**
  それ以外(=日々の変更適用)では`schema.sql`は使わない
- **本番は既に運用中でユーザーの実データが入っている。テーブルやデータを削除する
  ような変更(`DROP TABLE`、`DELETE`、既存データを上書き/巻き戻すような`UPDATE`等)は
  極力行わない。** カラムの追加(`ALTER TABLE ADD COLUMN`)や新規テーブルの追加
  (`CREATE TABLE IF NOT EXISTS`)など、既存データに影響しない変更のみを基本とする。
  どうしても削除的な変更が必要な場合は、影響範囲(消えるデータ・対象範囲)を明示した
  上で、**必ず作業前に承認を得ること**
- `migration.sql`には**まだ本番へ適用していないスキーマ変更のみ**を、末尾に
  `-- @STEP: 名前`ブロックとして追記していく。適用が完了したブロックは、
  ファイルからは削除し(内容は`schema.sql`に反映し、必要なら
  `archive/migrations/`へ退避する)、常に「これから適用すべき差分だけ」が
  ファイルに残っている状態を保つ

### スキーマ変更の適用手順(手動・wranglerのみ)

1. `migration.sql`に新しい`-- @STEP: 名前`ブロックを追記する
2. そのブロックのSQLだけを一時ファイル(例: `step.sql`)にコピーし、まず`--local`で試す

   ```bash
   npx wrangler d1 execute keiba-yosou-db --local --file=step.sql
   ```
3. 問題なければ`--remote`(本番)に適用する

   ```bash
   npx wrangler d1 execute keiba-yosou-db --remote --file=step.sql
   ```
4. 成功したら`schema_migrations`に適用記録を追加する

   ```bash
   npx wrangler d1 execute keiba-yosou-db --remote --command "INSERT INTO schema_migrations (name) VALUES ('新しいステップ名');"
   ```
5. `migration.sql`から該当ブロックを削除し、`schema.sql`へ内容を反映する(新規DBでも
   最初から最新構造になるように)

途中で失敗した場合は、`ALTER TABLE ADD COLUMN`のような非破壊的な変更なら
「既に列がある」旨のエラーで気づけるので、`PRAGMA table_info`等で実際に
どこまで反映されているかを確認してから、schema_migrationsへの記録や
残りのSQLを個別に対応する。`DROP`/`RENAME`を伴う変更は再実行すると
データを壊す恐れがあるため、特に慎重に確認すること。

更新後に再デプロイします。

```bash
npx wrangler pages deploy public --project-name=keiba-yosou-app
```

> 注意: `migration.sql` は既存DBを最新版へ更新するためのものです。新規DBは `schema.sql` を使用してください。
> 既存DBに複数ユーザー対応のマイグレーションを適用した場合は、管理者アカウント作成後に
> `archive/migrations/assign_existing_data_to_admin.sql` を1回実行して、既存データを管理者アカウントに割り当ててください
> (下記「複数ユーザー対応について」参照)。


## セットアップ手順(新規の場合)

### 1. Wranglerのインストール・ログイン

```bash
npm install -g wrangler
wrangler login
```

### 2. D1データベースを作成

```bash
wrangler d1 create keiba-yosou-db
```

実行結果に表示される `database_id` をコピーし、`wrangler.toml` の
`database_id = "ここに..."` の部分に貼り付けてください。

### 3. テーブルを作成

```bash
wrangler d1 execute keiba-yosou-db --remote --file=./schema.sql
```

`schema.sql` には、初期管理者アカウント(ユーザー名 `admin` / パスワード `password`)が
自動的に登録されます。デプロイ後、必ずログインしてパスワードを変更する運用に切り替えてください
(現時点ではアプリ内にパスワード変更機能が無いため、変更する場合はDBを直接更新してください)。

### 4. Cloudflare Pagesにデプロイ

```bash
wrangler pages deploy public --project-name=keiba-yosou-app
```

### 5. 環境変数とD1バインディングをダッシュボードで設定

Cloudflareダッシュボード → Workers & Pages → keiba-yosou-app → Settings で以下を設定:

- **Variables and secrets**:
  - `APP_PASSWORD`: 好きな文字列を設定(Secret推奨)。ログイン用パスワードとしては使われず、
    **セッションCookieの署名用シークレット**として使われる。値そのものに意味は無いので、
    他人に推測されにくいランダムな文字列を設定しておけばよい
  - `ADMIN_USERNAMES`: 管理者にしたいユーザー名をカンマ区切りで設定(例: `admin` または
    `admin,papa`)。ここに載っているユーザー名でログインした人だけが、レース情報の登録・編集や
    管理画面(未登録レース一覧・登録ユーザー一覧)を利用できる
- **Bindings**: D1 database の変数名を `DB` にして `keiba-yosou-db` を紐付け

設定後、もう一度手順4のコマンドを実行すると反映されます。

### 6. 完成

発行されたURLにPC・スマホからアクセスし、ログイン画面の「新規ユーザー登録」から
ユーザーを作成してください(招待コード等は無く、URLを知っていれば誰でも登録できます)。
管理者にしたいユーザーは、登録後に上記の `ADMIN_USERNAMES` へユーザー名を追加してください。

## 複数ユーザー対応について

- ログイン画面から誰でも自己登録できます(ユーザー名+パスワード)。招待コードの仕組みは
  ありません
- 管理者かどうかは、Cloudflare Pagesの環境変数 `ADMIN_USERNAMES` で判定します。DBにフラグは
  持っていないため、環境変数を編集するだけで管理者を増減できます
- レース情報(日付・出走馬・着順・払戻など)は全ユーザー共有のデータで、登録・編集・削除は
  管理者のみが行えます。それ以外(購入履歴・CSVインポート履歴・予想印・予想メモ・馬メモ)は
  ユーザーごとに完全に分離されており、他のユーザーからは見えません
- CSVインポート時に該当レースがまだ登録されていない場合、レースは自動登録されません。
  未登録のまま取り込まれたデータは、管理画面(`admin.html`)の「未登録レース一覧」から確認でき、
  管理者がそのレースを登録すると自動的に紐付きます
- 個別ログイン導入前に登録されていた購入履歴・CSVインポート履歴・予想印・予想メモ・馬メモは、
  DBマイグレーション直後は「誰のものか」の情報を持たない(user_idがNULL)状態になっています。
  管理者アカウントを作成した後、`archive/migrations/assign_existing_data_to_admin.sql` を
  1回実行すると、それらすべてが管理者アカウントの所有として割り当てられます
  ```bash
  wrangler d1 execute keiba-yosou-db --remote --file=./archive/migrations/assign_existing_data_to_admin.sql
  ```
  (管理者のユーザー名を `admin` から変更した場合は、ファイル内の `'admin'` を実際の
  ユーザー名に書き換えてから実行してください)
- ユーザー削除機能・パスワードリセット機能は現時点では実装していません(`docs/BACKLOG.md`に
  将来タスクとして記録済み)
